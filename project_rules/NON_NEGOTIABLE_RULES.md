# FraudRoko - Non-Negotiable Development Rules

Version: 1.0

Status: Active

These rules are mandatory and must NEVER be ignored by any developer or AI assistant working on this project.

---

# Rule 1 — Zero Guessing

Never guess any code, file, package name, class name, import, configuration, dependency, or project structure.

Always inspect existing files before making changes.

If any information is missing, stop and ask.

---

# Rule 2 — Never Delete Existing Work

Never delete, overwrite, or replace existing files, folders, or code without my explicit approval.

Always preserve previous work.

---

# Rule 3 — No Breaking Changes

Never rename folders, files, packages, classes, variables, or architecture without approval.

Maintain backward compatibility whenever possible.

---

# Rule 4 — Explain Before Coding

Before writing or modifying any code:

- Explain what will change.
- Explain why the change is required.
- Mention which files will be affected.
- Wait for approval if the change is significant.

---

# Rule 5 — Google Play Compliance

Every feature must comply with the latest Android and Google Play policies.

Never implement features that violate privacy, permissions, or Play Store requirements.

---

# Rule 6 — Build Real Features Only

Never create fake functionality.

Every scan, report, warning, score, or recommendation must be based on actual Android APIs, verified logic, or real analysis.

Never make fake antivirus claims.

Never mislead users.

---

# Rule 7 — Keep Architecture Clean

Write clean, modular, scalable, and production-ready code.

Separate:

- UI
- Business Logic
- Services
- Repositories
- Models

Avoid duplicate code.

---

# Rule 8 — Minimum Permissions

Request only the permissions required for the feature being used.

Never ask for unnecessary permissions.

Always request permissions only when the user starts that specific feature.

---

# Rule 9 — Every Problem Must Have a Solution

FraudRoko is a Cyber Safety Assistant, not just a scanner.

Whenever a problem is detected:

- Explain the issue.
- Explain the risk.
- Provide a "Fix Now" action whenever Android allows it.
- Guide the user step by step.

Never leave the user without a solution.

---

# Rule 10 — Quality Over Speed

Never rush development.

Planning comes before coding.

Architecture comes before features.

Testing comes before release.

A stable, maintainable, and trustworthy application is always more important than delivering features quickly.

---

# Final Principle

FraudRoko exists to protect users, educate them, and guide them.

It should never create unnecessary fear.

Every feature must increase user trust.

Every decision should respect user privacy.

Every feature must provide real value.

Always build for long-term maintainability.
